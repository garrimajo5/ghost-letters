# Кабинет карточек

Администратор открывает «Карточки (кабинет)» в меню главного экрана. Доступ задаётся существующим `Admin:UserIds`, как для ботов; сервер проверяет права при чтении разметки и каждом сохранении.

Можно найти карту по идентификатору или названию, отфильтровать набор и активность, изменить название, участие в новых партиях, набор, цвет/форму, смыслы и мелкие детали. Список разбит на страницы по 40 карт. Если другой администратор уже сохранил карту, устаревшее сохранение отклоняется: нужно открыть карту заново.

## Смыслы и поведение ботов

У смысла есть общий ключ связи, читаемая подпись и вес. Одинаковый ключ на разных картах создаёт связь; подпись используется в объяснениях бота. Вес 1 означает основной образ, меньший вес — второстепенный. В характере бота добавлен ползунок «Второстепенные смыслы»: 0 игнорирует их, 1 учитывает с заданными весами. Это отдельный параметр от внимания к мелким деталям. Старые смысловые теги считаются основными с весом 1; отсутствующие образы автоматически не придумываются.

Пример: у розы «цветок» весит 1, «воспоминание» — 0.4. Бот с ползунком 0 не будет связывать её с другой картой только через воспоминание. Более восприимчивый бот сможет учитывать эту связь и назвать её в обсуждении. Сила связи растёт с весом и вниманием бота.

## Сохранение и обновление

Изменения хранятся в PostgreSQL поверх исходных tags.json/details.json. Разметка загружается один раз на такт ботов и не требует перезапуска сервера. Ручной перенос карты защищён от обратного переноса при импорте манифеста; повторное заполнение каталога не создаёт копию такой карты. Выключение и перенос влияют на колоды новых партий; уже выданные карты остаются в идущей партии.

`GET /api/v1/cards/sets` возвращает авторизованным игрокам активный состав наборов без разметки. `GET /api/v1/admin/cards` и `PUT /api/v1/admin/cards/{id}` доступны только администратору. Клиент использует серверный каталог, а при недоступности API — встроенный; окончательный состав новой колоды всегда определяет сервер.

Миграции CardAdministration и BotSecondaryMeanings добавляют поля без удаления данных. Для существующих ботов начальное внимание к второстепенным смыслам — 0.35.
