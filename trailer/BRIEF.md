# Трейлер «Письма призрака» — задача для Codex

Смонтировать трейлер игры длиной **1:35** под готовый музыкальный монтаж. Вся раскладка ниже привязана к тактам трека, поэтому склейки должны попадать в сильные доли.

## 1. Что сдать

1. `trailer/out/ghost-letters-trailer-16x9.mp4`:
   - видео 1920×1080, 30 fps, H.264 (yuv420p, `-movflags +faststart`);
   - звук AAC 192 kbps;
   - длительность ровно по музыке, 94,78 с;
   - размер файла не больше 40 МБ (подобрать CRF или битрейт).
2. Скрипт сборки, который пересобирает ролик одной командой (`trailer/build.*` + README):
   - инструмент на ваш выбор: Remotion, Python + ffmpeg, MoviePy или HTML-сцены + Playwright-рендер;
   - все тексты, тайминги и пути к картинкам — в одном конфиге (`trailer/scenes.json` или аналог), чтобы владелец мог поправить надпись и пересобрать.
3. Скриншоты игры, снятые для ролика: `trailer/captures/*.png` и короткие записи экрана `*.webm`/`*.mp4`, если понадобятся.
4. Необязательно, но желательно: вертикальная версия `ghost-letters-trailer-9x16.mp4` (1080×1920) тем же монтажом, с перекомпоновкой кадров, а не с чёрными полями.

Работа идёт отдельной веткой и PR в main. Код приложения и сервера не меняется, всё лежит в `trailer/`.

## 2. Музыка

- `trailer/music/trailer_music_1m35.mp3` — **использовать именно его**:
  - уже смонтирован из полного трека: три куска, склейки на сильной доле, 40 мс кроссфейд;
  - громкость −14 LUFS, пик −2,9 dBFS;
  - музыку не резать и не ускорять.
- `trailer/music/markers.json`:
  - темп 129,24 BPM, доля 0,46425 с, такт 1,857 с;
  - время начала каждого такта (`bars`);
  - разделы трека (`sections`);
  - **все склейки картинки ставить на `bars[i]` или на доли внутри такта.**
- `source_first_launch_suno.mp3` и `edit_music.py` — исходник и скрипт музыкального монтажа, на случай если понадобится пересобрать.

## 3. Стиль

- **Настроение:** нуарный детектив, ночь, туман, синие сумерки, тёплые янтарные акценты. Тайна, а не хоррор: без скримеров и крови крупным планом.
- **Цвета** (из `client/lib/core/theme.dart`):

  | Назначение | Цвет |
  |---|---|
  | Фон | `#0D1724` |
  | Ночь | `#0A111B` |
  | Панели | `#152335` |
  | Рамки | `#2B4260` |
  | Текст | `#E8EEF4` |
  | Янтарь (главный акцент) | `#E3A94B` / `#F2C579` |
  | Ледяной голубой (призрак) | `#A9D4EA` |
  | Красный (убийца) | `#B03E33` |
  | Зелёный (верно) | `#3FBF7F` |

- **Шрифты** (в `client/assets/fonts/`):
  - заголовки — Oswald 600/700, ЗАГЛАВНЫМИ, разрядка 1–2 px;
  - подписи — Golos Text 500.
- **Движение:**
  - медленные наезды (Ken Burns, 3–6 % за сцену) и параллакс по слоям;
  - дрейфующий туман: мягкий шум или спрайты поверх кадров, непрозрачность 10–25 %;
  - пылинки-«светлячки» голубого цвета вокруг призрака;
  - карты появляются с лёгким поворотом и свечением;
  - на дропе и в припеве — резче: смены по долям, лёгкий shake или зум-панч на ударах, вспышка 2–3 кадра.
- **Текст на экране:**
  - короткие фразы по 2–6 слов, максимум 2 строки;
  - не меньше 1,5 с на прочтение;
  - появление: fade + подъём на 12 px, исчезновение: fade;
  - безопасная зона 5 % по краям.
- **Скриншоты приложения:**
  - показывать в рамке телефона (простой скруглённый прямоугольник `#0A111B` с тонкой рамкой `#2B4260`, без логотипов Apple/Google);
  - рамка на фоне размытого тумана;
  - крупные детали снимать зумом внутрь скриншота, а не растягиванием.

## 5. Снять экраны приложения

Нужны настоящие экраны игры. Способ A предпочтителен, способ B — для состояний, которые трудно поймать вживую.

**A. Живая партия с ботами.**

1. Подготовка:
   - `docker compose up -d --build` → API на `localhost:8080` (см. `docs/local-dev.md`);
   - `cd client && flutter build web --release --dart-define=API_URL=http://localhost:8080`;
   - раздать `build/web` локально: `python -m http.server 8000`, как в CI. Локальный API в режиме Development разрешает CORS с любого порта.
2. Съёмка через Playwright (Chromium уже есть):
   - портретный телефон: viewport 412×915, deviceScaleFactor 3;
   - альбомная ориентация для кадра «планшет»: 1366×1024, deviceScaleFactor 2.
3. Партия:
   - войти гостем;
   - в кабинете ботов создать готовые характеры. Нужны права админа: id гостя (есть в профиле) прописать в переменную `Admin__UserIds` сервиса `api` через локальный `docker-compose.override.yml` (не коммитить) и перезапустить `api`;
   - создать лобби: 4 ряда с «Тайной», 5 столбцов, роли Убийца + Сообщник + Свидетель, живой темп, таймеры покороче;
   - добавить 5–6 ботов с характерами, стартовать.
4. Роль хоста случайная. Чтобы снять ночь Убийцы и подсказки Сообщников, перезапускать партию, пока не выпадет Убийца или Сообщник. Экран стола (вход «как экран стола») даёт общий вид поля.

**B. Детерминированно через тестовые фикстуры.**

- Клиентские тесты рендерят любой экран с любой ролью и фазой: `client/test/support/fakes.dart`, `fixtures.dart`.
- Можно написать отдельный тест-«фотограф»:
  - класть его в `trailer/capture/`, не в `client/test/`, чтобы не попал в CI;
  - загружать реальные шрифты через `FontLoader` и прогревать картинки (`precacheImage` в `tester.runAsync`);
  - сохранять PNG через `RepaintBoundary.toImage`.

## 7. Проверка перед сдачей

- **Синхрон:** склейки совпадают с `markers.json`.
  - Скрипт проверки печатает таблицу «сцена → время → ближайшая доля → расхождение».
  - Расхождение ≤ 1 кадр (33 мс).
- **Длительность:** `ffprobe` показывает 94,7–94,9 с; звук без изменений — средняя громкость −14 ±0,5 LUFS (`ffmpeg -af ebur128`).
- **Кадры:**
  - выгрузить по кадру из середины каждой сцены (`trailer/out/contact_sheet.jpg`);
  - нет растянутых или пиксельных картинок: иллюстрации 360 px не увеличивать больше чем в 1,6 раза, ставить их на фон или в рамку;
  - текст читается, без опечаток и без обрезки краёв.
- **Состав PR:** только `trailer/`, mp4 до 40 МБ.
